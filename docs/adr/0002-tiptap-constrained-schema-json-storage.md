# Tiptap WYSIWYG with constrained schema, JSON storage, custom React renderer

For the Warranty page rich body we picked Tiptap with an explicit allow-list of nodes/marks (paragraph, H2, bold, italic, link, bullet/numbered list, custom callout with `destructive`/`warning` variants, separator). Output is stored as Tiptap JSON in a `Json` column and rendered via a custom React component that walks the tree and maps each node type to the corresponding shadcn component (callouts → `<Alert>` with the matching variant + `AlertTriangle`, separator → `<Separator>`, link → `<a>` with `rel="noopener noreferrer"` for external).

Markdown was rejected because the authoring brief required a "made with care, not a text box" experience and we did not want admins learning admonition syntax. HTML storage was rejected because it forfeits the property that callouts render as actual `<Alert>` components (HTML can only style `<div>`s via CSS) and adds a sanitisation surface. The constrained schema plus JSON-to-React pipeline keeps the design system in charge of what visitors see regardless of which buttons an admin clicks, eliminates `dangerouslySetInnerHTML` and any XSS risk from authored content, and makes future schema evolutions a programmatic JSON transform rather than a regex over HTML strings.
